# 課程分享、資料備份與還原

## 先選對檔案

| 檔案 | 包含 | 適合用途 | 能否公開 |
| --- | --- | --- | --- |
| 課程 JSON | 教材、活動、設定及自訂 HTML | 分享教材、交給 agent 修改 | 先確認素材與內容授權 |
| 場次 JSON／CSV | 該次上課的作答紀錄 | 教師分析與紀錄保存 | 通常不適合 |
| 教師備份 JSON | 所管理的課程、班級及課堂資料；不含登入憑證 | 資料備援與還原 | 不可作為公開範例 |
| Supabase 平台備份 | 視平台方案與設定而定 | 災難復原、整體資料庫維護 | 私下保管 |

教師備份排除密碼、識別碼雜湊、cookie 與 API key。這不代表它已匿名：答案、座號與課堂脈絡仍可能辨識學生，應放在受保護的位置。

## 建議流程

1. 教師結束課堂後下載場次紀錄，確認能讀取且包含預期題目與答案數量。
2. 重要課程變更前下載課程 JSON；保留版本或日期。
3. 定期下載教師備份，存於學校核可的位置。檔名可包含日期，但不包含學生姓名。
4. 在獨立測試環境演練還原。驗證課程數、場次、投影片快照與作答內容，而不是只看匯入成功訊息。
5. 雲端平台的帳號、Secrets、教師 Auth 身分與學生識別碼需另外管理；課程匯入不會替你重建它們。

本機 demo 資料保存在 `.wrangler/state`。停止後再啟動通常能保留示範紀錄；刪除該目錄會重置本機資料。這不是正式備份策略，不要將它提交 Git。

## 還原的實際行為

還原採驗證後合併，不接受備份檔中的外部擁有者身分。**相同 ID 的自己的課程會由備份內容更新**；既有自己的班級與場次保留，不重複匯入。若 ID 與其他教師資料衝突則拒絕。請先下載目前備份，再還原較舊資料。

新匯入班級重新對應 ID，匯入的場次保持「已結束」，不會突然讓學生進入歷史課堂。

備份不含學生憑證，因此新匯入班級的座號預設無可用識別碼。要繼續使用該班，到「班級與學生」依座號重發識別碼，再分別交給學生。新識別碼只在重發後顯示，應立即妥善保存。重發會撤銷舊登入；這不是將舊的學生密碼還原回來。

「課堂紀錄」提供備份下載與還原。Agent 也可使用 `POST /api/restore` 與 `POST /api/classes/:id/credentials`，但仍需在測試環境驗證資料內容。不要手動編輯正式 snapshot 來繞過還原驗證。

備份還原請求上限 **9 MiB**；合併後的全部資料 snapshot 上限 **8 MiB**，所以檔案大小合格仍可能因現有資料加總超限而被拒絕。前端課程匯入約 1 MiB；大的教材應拆課或精簡內嵌素材。這些限制適用於 v0.1，小型示範以外的長期資料保存應另行評估。

## 升級與資料遷移

`schemaVersion` 是教材格式版本，不是 Supabase migration 版本。新增正式資料表或修改儲存格式時：

1. 保存目前程式版本與備份，確認可還原。
2. 先在測試 Supabase 套用 migration，測試舊課程與舊場次。
3. 針對資料轉換寫出前後條件，例如答案總數、活動 ID、正解與筆跡保持一致。
4. 驗證角色權限後再升級正式環境。
5. 保留舊程式與備份的回復方法；不要把已套用 migration 的資料庫直接當作未升級版本使用。

本版沒有自動排程備份、保存天數清除或災難復原管理介面。部署者需自行安排備份與刪除政策，並查看實際 Supabase 方案的備份能力。[Supabase 備份文件](https://supabase.com/docs/guides/platform/backups)
