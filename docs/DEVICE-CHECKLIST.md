# 大觸控螢幕與 iPad 驗收

開發時以觸控為主要操作方式：一般主要按鈕至少 48px，教師教學工具使用約 64px 的觸控區；不依賴 hover 才能找到功能。真實裝置仍需逐項驗收，桌面瀏覽器的模擬觸控不能驗證驅動、觸控筆或 iPad Safari 的全部行為。

## 教師大觸控螢幕

- [ ] 記錄螢幕型號、解析度、作業系統縮放比例、瀏覽器和版本。
- [ ] 手指可操作登入、開課、換頁、開題、公布結果、抽籤與搶答控制。
- [ ] 手指與觸控筆各寫一段；抬筆不連出多餘線，畫筆模式中不誤觸捲動。
- [ ] 切回操作工具後可點按投影片上的活動與工具。
- [ ] 筆跡可復原／清除，換頁後不混入別頁，刷新後可讀回已保存筆跡。
- [ ] 雷射筆與聚光燈可用按下／拖移操作，不要求 hover。
- [ ] 全螢幕／離開全螢幕不裁切工具列；必要時使用瀏覽器全螢幕替代。
- [ ] 投影模式不顯示學生識別碼、金鑰設定與未選擇公開的個別回答。
- [ ] 共用設備登出後，學生不能透過返回頁面取得教師資料。

## 學生 iPad Safari

- [ ] 記錄 iPad 型號、iPadOS 版本、Safari 版本／設定及網路。
- [ ] 直向、橫向及旋轉後能看完整題目與送出按鈕，沒有橫向溢出。
- [ ] 班級、座號與識別碼可輸入；螢幕鍵盤不遮住必要欄位。
- [ ] 用相機掃描正式部署的班級 QR Code 可開啟正確入口；本機 loopback 網址不可當作跨裝置驗收。
- [ ] 單選、多選、量尺、短答和 customHtml 示例都可用手指完成。
- [ ] 短答鍵盤開啟時仍能找到送出與保存狀態。
- [ ] 背景切換／鎖定再返回能恢復場次；核對已送答案與目前頁面。
- [ ] 暫時斷網後，不會把未送出的內容錯標為已儲存；恢復連線後確認結果。
- [ ] 放大文字或使用鍵盤操作仍可完成主要流程。
- [ ] 教師切頁、關題、公布結果後，學生在合理同步時間內收到更新。

## 整班網路

- [ ] 先做 1 位教師＋2 位學生，通過後再做全班 40 台目標驗收。
- [ ] 記錄提交成功率、從操作到更新的延遲、斷線次數及伺服器錯誤。
- [ ] 全班同時送出不遺失答案；重送不增加重複紀錄。
- [ ] 搶答只產生一位有效勝出者；說明網路延遲會影響後端收到的順序。
- [ ] 離開／返回 App、Wi-Fi 切換與教師刷新不造成跨班或場次混淆。

完成後將結果填入 [VALIDATION.md](VALIDATION.md)，分別標示「實機通過」、「模擬通過」或「未測」。
